## 1. Краткое описание плагина

`dsh-voice-chat` — это **плагин голосового диалога в стиле Doubao** для DeepSeek Harness (DSH) Web GUI. Он добавляет кнопку микрофона рядом с полем ввода чата:

- **Говори**: нажми 🎤 для начала записи, после паузы запись автоматически завершается, речь преобразуется в текст и отправляется AI;
- **Слушай**: ответы AI синтезируются в речь через TTS и озвучиваются (бесплатный Edge TTS с русскими голосами / MiMo TTS / пользовательский TTS / браузерный синтез / офлайновый Piper);
- **Опциональный пересказ**: при включении «сокращения длинных ответов» они сперва сжимаются и пересказываются LLM от лица «самого помощника», а затем озвучиваются;
- **Русский язык** в интерфейсе и по умолчанию для речи; язык и скорость озвучки переключаются в настройках;
- **Офлайн и живой диалог**: локальный движок (faster-whisper + Piper) работает без ключей и сети, а режим «Постоянный диалог» убирает необходимость каждый раз нажимать 🎤.

## 2. Функции

| Функция | Описание |
|---|---|
| 🎤 Голосовой ввод | Нажать для начала записи (сигнал «динь») → говорить → тишина 2.5 с для автоматического завершения («дон») → распознавание и отправка |
| 🗣️ Пересказ с озвучиванием | (По умолчанию выключено) При включении: длинные ответы сначала сжимаются LLM (≤ оригинала, без кода и таблиц), затем озвучиваются TTS; модель пересказа автоматически следует за текущей LLM диалога |
| 🔊 TTS-движки | **Edge TTS** (Microsoft, бесплатно), **MiMo TTS** (Xiaomi, встроенные китайские голоса), **пользовательский TTS** (OpenAI-совместимый), **браузерный** (`speechSynthesis`, офлайн), **локальный** (Piper, офлайн) |
| 🎤 ASR-движки | **SiliconFlow** (бесплатно), **Groq** (Whisper), **MiMo** (Xiaomi, протокол chat/completions), **пользовательский** (OpenAI-совместимый), **браузерный** (Web Speech API, без ключа), **локальный** (faster-whisper, офлайн) |
| 🗣️ Язык и скорость речи | Язык речи ru-RU / zh-CN / en-US / ja-JP (по умолчанию русский) и ползунок скорости озвучки 50–200 % (по умолчанию 110 %) |
| 🔁 Постоянный диалог | После ответа AI микрофон включается сам, речь поверх озвучки прерывает её (см. 6.5) |
| 📴 Офлайн-движок | Локальный faster-whisper + Piper: плагин сам разворачивает portable Python, venv и модели, ключи и сеть не нужны (см. 7.1) |
| 🔇 Переключатель звука | Нажать во время воспроизведения для **немедленной остановки**; после отключения звука автоматическое озвучивание не происходит |
| ⏪ Одноканальное воспроизведение | Новый ответ прерывает предыдущее воспроизведение; горячие клавиши/запись могут прервать, в любой момент звучит только один голос |
| 🔁 Защита от повторного воспроизведения | Запоминает озвученные ответы по сессиям, при повторном входе в сессию не озвучивает повторно |
| ⌨️ Клавиша запуска речи | По умолчанию **правый Ctrl**: **держите** — идёт запись, **отпустили** — распознавание и отправка. Клавиша/сочетание выбирается в настройках (см. 6.3) |
| ⚙️ Панель настроек | Изменять напрямую во встроенном диалоге настроек DSH, изменения применяются сразу после сохранения, без перезапуска |
| 🔄 Конвертация записи | MiMo и другие ASR по chat-протоколу поддерживают только wav/mp3, браузерная запись (webm) автоматически конвертируется в 16kHz моно WAV |

## 3. Системные требования

- **DeepSeek Harness** (dsh) установлен и запущен Web GUI (`dsh web`);
- **Node.js ≥ 22** (единственная рантайм-зависимость — `ws`);
- **Браузер**: Chrome / Edge (для записи нужен `MediaRecorder`, для браузерных движков — `SpeechRecognition` / `speechSynthesis`);
- **ASR-ключ**: нужен только для облачных движков; SiliconFlow предоставляет бесплатный лимит при регистрации, MiMo платный по использованию (около 0.5 юаня/час);
- **TTS**: Edge TTS бесплатен и не требует ключа; MiMo TTS / пользовательский TTS требуют соответствующих ключей;
- **Для офлайн-движка** дополнительных системных зависимостей нет: portable Python скачивается автоматисто (или задайте свой интерпретатор через `DSH_VOICE_PYTHON`).

## 4. Установка

```bash
# Этот форк (установка по git-адресу):
dsh plugin --profile web add https://github.com/AlekseiShchemelev/dsh-voice-chat-ru.git

# Оригинальная версия (опубликована в npm):
dsh plugin --profile web add dsh-voice-chat

# Перезапустите dsh web для активации плагина
```

После успешной установки:
- Плагин автоматически регистрируется на уровне profile (в `bundles` файла `~/.dsh/profiles/web/package.json` появляется `dsh-voice-chat`);
- После обновления страницы в браузере справа от поля ввода появляются кнопки 🎤 и 🔊.

## 5. Быстрый старт (5 минут)

1. **Обновите страницу** (Ctrl+Shift+R), убедитесь, что справа от поля ввода появилась кнопка 🎤;
2. Настройте движок распознавания (облачному — ключ; браузерному и локальному ключ не нужен, см. [Руководство по настройке](#7-руководство-по-настройке));
3. **Нажмите 🎤** → услышите «динь» → начните говорить;
4. После паузы около 2.5 секунд → услышите «дон» → речь автоматически преобразуется в текст и отправляется;
5. После получения ответа AI **автоматическое озвучивание**.

> 💡 Хотите быстрее? Держите **правый Ctrl** — запись начнётся сама, отпустите клавишу — текст уйдёт в чат (клавишу можно заменить в настройках, см. [6.3](#63-клавиша-запуска-распознавания)).

## 6. Руководство по использованию

### 6.1 Кнопки

| Кнопка | В состоянии покоя | После нажатия | Описание |
|---|---|---|---|
| 🎤 Микрофон | Серый | Становится красным ● запись | Повторное нажатие = завершить и отправить |
| 🔊 Переключатель звука | Серый | Оранжевый при воспроизведении / красный 🔇 при отключении | Нажать во время воспроизведения = немедленно отключить звук; повторное нажатие = восстановить автоматическое озвучивание |
| ⚙️ Доступ к настройкам | Кнопка настроек в левом нижнем углу | Открывает диалог настроек DSH | Категория «voice chat» слева: выбор движков ASR/TTS, настройка API, голосов и т.д.; изменения применяются сразу после сохранения |

### 6.2 Процесс голосового взаимодействия

```
Нажать 🎤 или удерживать клавишу запуска (по умолчанию правый Ctrl) → динь → [Запись…] → говорить → отпустить клавишу (или пауза 2.5 с — можно изменить в настройках)
→ дон → распознавание… → текст вставляется в поле ввода и автоматически отправляется (можно изменить на только вставку)
→ ответ AI → озвучивание (при включенном «пересказе с озвучиванием»: сначала LLM сжимает, от лица помощника, затем озвучивание, по умолчанию выключено)
→ в процессе можно нажать 🔊 для остановки / удерживать клавишу запуска, чтобы перебить озвучку и говорить заново
```

### 6.3 Клавиша запуска распознавания

Действие — **удержание** (push-to-talk): нажали клавишу → запись пошла, отпустили → запись остановилась, запись ушла на распознавание и (по умолчанию) отправилась. Удерживать клавишу удобно большим пальцем, не отпуская мышь; если микрофон уже пишет, нажатие игнорируется, а отпускание завершает запись.

| Что | Как |
|---|---|
| Клавиша по умолчанию | **Правый Ctrl** (`ControlRight`) — не конфликтует с `Ctrl+C` / `Ctrl+V` (левый Ctrl) |
| Смена клавиши | Настройки DSH → голосовой чат → «Клавиша запуска распознавания»: нажмите на поле, затем нужную клавишу или сочетание |
| Сброс | `Esc` в поле или кнопка «Правый Ctrl» |
| Отключить | `Delete` в поле или кнопка «Выключить» (поле покажет «не задана») |
| Где хранится | `asrHotkey` в `settings.local.json` (строки: `ControlRight`, `Ctrl+Shift+Space`, `Ctrl+Alt+M`; пусто — выключено) |

Поддерживаются одиночные модификаторы (левые/правые `Ctrl`, `Shift`, `Alt`, `Cmd`/`Win`), сочетания с ними, буквы, цифры, `Space`, `Enter`, `Tab`, стрелки. Автоповтор при удержании игнорируется, а уход со вкладки во время записи её корректно завершает.

> Старые жёстко зашитые `Ctrl+Shift+Space` и `Ctrl+M` убраны — используйте настраиваемую клавишу.

### 6.4 Индикаторы состояния

- **Звуковые сигналы**: начало «динь» (880 Гц), завершение «дон» (523 Гц), короткие и мягкие;
- **Всплывающие подсказки**: состояния записи/распознавания/ошибок и т.д. кратковременно отображаются над кнопкой;
- **Цвет кнопок**: запись красный, распознавание жёлтый, воспроизведение оранжевый, отключение звука красный.

### 6.5 Постоянный диалог (живое общение)

Включается галочкой «Постоянный диалог» в ⚙️ → голосовой чат → Настройки распознавания речи.
После этого не нужно каждый раз нажимать 🎤:

- **Автопродолжение**: как только AI договорил (озвучивание закончилось), микрофон снова включается сам — можно говорить следующую фразу;
- **Перебивание**: если начать говорить поверх озвучки, AI замолкает на середине и сразу записывается ваша речь (срабатывает после ~0.45 с непрерывного звука, чтобы не реагировать на случайный шум);
- **Автоотправка** в этом режиме всегда включена: если у вас отключена обычная автоотправка, текст всё равно уйдёт сразу — иначе диалог прервётся;
- **Как остановить**: нажать 🎤 ещё раз (цикл не продолжится), нажать 🔊 (выключить звук — цикл тоже не продолжится) или снять галочку в настройках.

Требуется разрешение браузера на микрофон; во время озвучки он открывается вторым потоком только для контроля громкости.

## 7. Руководство по настройке

### ⚙️ Панель настроек (рекомендуется, наивысший приоритет)

Откройте диалог настроек DSH (шестерёнка в левом нижнем углу), слева выберите «**voice chat**», справа можно изменить:

**🎤 Настройки распознавания речи**
- Движок ASR (SiliconFlow / Groq / MiMo / пользовательский / браузерный / локальный)
- Base URL / название модели / API Key для каждого движка отдельно
- Автоматическая отправка после распознавания
- Длительность тишины для автоматического завершения (сек)
- Постоянный диалог (живое общение, см. 6.5)

**🔊 Настройки озвучивания**
- Движок TTS (Edge TTS / MiMo TTS / пользовательский / браузерный / локальный)
- Base URL / название модели / API Key / голос для каждого движка отдельно
- Ползунок **скорости речи** (50–200 %, по умолчанию 110 %)
- Выбор **языка речи** (Русский / Китайский / Английский / Японский)
- Переключатель сокращения длинных ответов перед озвучкой (по умолчанию выключен)

> 🔒 **Каждый движок ASR / TTS имеет отдельную конфигурацию**: переключение движка просто «переключает просмотр»,
> Base URL / модель / API Key / голос каждого движка не перезаписывают друг друга, при сохранении записывается
> только текущая редактируемая конфигурация.
> Если ключ для MiMo TTS оставить пустым, используется только ключ из конфигурации «MiMo ASR» (тот же провайдер),
> ключи других движков не используются. Старая единая конфигурация (≤0.3.x) автоматически мигрирует на соответствующий
> движок при первом запуске: голос с суффиксом `Neural` → Edge; предустановленные голоса MiMo → MiMo TTS;
> остальные адреса/ключи → пользовательский TTS.

Изменения применяются сразу после сохранения, перезапуск не требуется.

### 📄 Файл конфигурации (низкий приоритет)

В файле profile `~/.dsh/profiles/web/cordis.patch.yml` можно переопределить config по id:

```yaml
- id: dsh-voice-chat
  name: 'dsh-voice-chat'
  config:
    # Настройки распознавания речи
    asrEngine: siliconflow            # Движок ASR: siliconflow | groq | mimo | custom | browser | local
    asrApiKey: sk-ваш-ключ             # Старый формат (действует на текущий движок; или переменная окружения DSH_VOICE_ASR_KEY)
    asrBaseUrl: https://api.siliconflow.cn/v1
    asrModel: FunAudioLLM/SenseVoiceSmall
    asr:                              # Для изоляции по движкам заполнить здесь (приоритет над плоскими ключами выше)
      local:  { baseUrl: http://127.0.0.1:8765/v1, model: small }
      custom: { baseUrl: http://127.0.0.1:8000/v1, model: whisper-v3, apiKey: sk-ваш-ключ }
    llmModel: deepseek-v4-flash       # Модель для пересказа (fallback, обычно следует за текущему диалогом)
    silenceMs: 2500                   # Через сколько миллисекунд тишины автоматически завершить запись
    hotkey: ControlRight              # Клавиша запуска распознавания (удержание; "" — выключить), см. 6.3
    continuousMode: false             # «Постоянный диалог» (живое общение, см. 6.5)
    # Настройки озвучивания
    rewrite: false                    # Сокращать длинные ответы перед озвучкой (по умолчанию выключено)
    ttsEngine: edge                   # Движок TTS: edge | mimo | custom | browser | local
    voice: ru-RU-SvetlanaNeural       # Голос Edge (эквивалентно tts.edge.voice)
    ttsBaseUrl: https://api.openai.com/v1   # Старый формат (действует на текущем движок)
    ttsModel: tts-1
    ttsApiKey: sk-ваш-ключ
    tts:                              # Конфигурация TTS по движкам (приоритет над плоскими ключами выше)
      edge:   { voice: ru-RU-SvetlanaNeural }
      local:  { baseUrl: http://127.0.0.1:8765/v1, model: piper, voice: ru_RU-irina-medium }
      mimo:   { baseUrl: https://api.xiaomimimo.com/v1, model: mimo-v2.5-tts, apiKey: sk-ваш-ключ, voice: 冰糖 }
      custom: { baseUrl: https://api.openai.com/v1, model: tts-1, apiKey: sk-ваш-ключ, voice: alloy }
    ratePercent: 110                  # Скорость речи, 50–200 (100 = нормальная)
    speechLang: ru-RU                 # Язык речи: ru-RU | zh-CN | en-US | ja-JP
    shortTextChars: 50
```

Переменные окружения: `DSH_VOICE_ASR_ENGINE`, `DSH_VOICE_ASR_KEY`, `DSH_VOICE_ASR_BASE_URL`, `DSH_VOICE_ASR_MODEL`, `DSH_VOICE_LLM_KEY`, `DSH_VOICE_LLM_BASE_URL`, `DSH_VOICE_LLM_MODEL`, `DSH_VOICE_HOTKEY` (клавиша запуска распознавания), а для офлайн-движка — `DSH_VOICE_PYTHON` (свой интерпретатор Python вместо portable) и `DSH_VOICE_DATA_DIR` (каталог данных и моделей).

### 7.1 Локальный (офлайн) движок

Движок `local` в списках ASR и TTS поднимает локальный HTTP-сервер на `127.0.0.1:8765` с faster-whisper (распознавание) и Piper (озвучка). Ключи и сеть не нужны — после загрузки моделей всё работает офлайн.

- **Ключ не нужен**: для движка `local` поля «API-ключ ASR/TTS» вообще не показываются, плагин не требует ключ и не отправляет заголовок авторизации локальному серверу;
- **Адрес задавать не нужно**: вместо «Base URL» у движка `local` один порт (по умолчанию `8765`), адрес `http://127.0.0.1:<port>/v1` плагин собирает сам и использует его же для автозапуска сервера — распознавание и озвучка всегда ходят на один и тот же порт;
- **Модель и голос — из списка**: «Модель распознавания» (`tiny`/`base`/`small`/`medium`/`large-v3`, по умолчанию `small`) и «Голос (локальный Piper)» (4 русских голоса, по умолчанию `ru_RU-irina-medium`). Значения из UI совпадают с тем, что принимает `py/server.py`;
- **Движок `browser` ничего не спрашивает**: ни адреса, ни модели, ни ключа — распознаёт/озвучивает сам браузер. Поля скрыты, чтобы не создавать впечатления, что что-то настраивается;
- **Проверка окружения** в блоке статуса идёт по шагам: Python → импорт `faster_whisper`/`piper-tts` → модели на диске → сервер. «venv есть» и «пакеты импортируются» — разные строки: venv-интерпретатор запускается даже без pip-пакетов;
- **Данные и модели**: `~/.local/share/dsh-voice-chat/` (или `DSH_VOICE_DATA_DIR`) — portable Python, venv, модели;
- **Первая установка** занимает несколько минут: `POST /dsh-voice-chat/local/install` (фоновая загрузка Python, pip-пакетов faster-whisper и piper-tts, затем моделей), состояние видно через `GET /dsh-voice-chat/local/status`;
- **Панель управления**: Настройки DSH → голосовой чат → движок ASR или TTS «Локальный» — появляется блок со статусом (Python / зависимости / модели / сервер) и кнопками «Установить локальный движок», «Запустить сервер», «Остановить сервер», «Обновить», **«Удалить локальный движок»**. Пока идёт установка или сервер не отвечает, статус обновляется сам раз в 2 с;
- **Удаление** требует подтверждения (кнопка меняется на «Точно удалить?»): останавливается сервер и сносятся portable Python, venv, модели и журналы — обычно освобождает 1–3 ГБ. Настройки движков и ключи не затрагиваются, движок ставится заново одной кнопкой. `POST /dsh-voice-chat/local/remove` (с `?keepModels=true` модели сохраняются);
- **Запуск/остановка**: `POST /dsh-voice-chat/local/start?port=8765` и `POST /dsh-voice-chat/local/stop`. Сервер поднимается **автоматически** при первом обращении к движку `local`, так что кнопка «Запустить» нужна только для диагностики. Порт берётся из адреса в поле «Base URL» слота `local` (если смените порт, он подхватится). Процесс Python останавливается при выгрузке плагина;
- **Озвучка**: Piper отдаёт WAV, поэтому `/tts` и `/speak` отвечают `Content-Type: audio/wav` (для остальных движков — `audio/mpeg`);
- **Декодирование аудио делает сам сервер** (`_decode_audio` в `py/server.py`): webm/opus, mp3 и WAV приводятся к float32 16 кГц моно и передаются модели массивом. Внутренний декодер faster-whisper не используется — в его версии 1.2.1 вызов `av.open(..., metadata_errors=...)`, которого нет в свежем PyAV (>=14), ломал распознавание ошибкой `open() got an unexpected keyword argument 'metadata_errors'`;
- **Язык распознавания** берётся из общей настройки «Язык речи» и передаётся локальному движку (`language` в multipart) — без него Whisper угадывает язык и часто ошибается;
- **Журнал установки**: каждый запуск пишет вывод Python в `<dataDir>/logs/install.log`, а его хвост показывается в блоке статуса («Последние строки журнала установки») — там и находится настоящая причина сбоя, а не «модели не загружены»;
- **Если модели не качаются** (сеть/прокси/антивирус): загрузчик сам повторяет попытки, использует таймауты и запасное зеркало. Своё зеркало Piper — переменная `DSH_VOICE_PIPER_BASE`, для faster-whisper — `HF_ENDPOINT` (например `https://hf-mirror.com`). Модели можно скачать и вручную в `<dataDir>/models`: `piper/ru_RU-irina-medium/ru_RU-irina-medium.onnx` + `.onnx.json` и каталог `models--Systran--faster-whisper-<размер>`;
- **Модели распознавания** (поле «Модель ASR»): `tiny`, `base`, `small` (по умолчанию), `medium`, `large-v3`;
- **Голоса Piper** (поле «Голос»): `ru_RU-irina-medium` (по умолчанию), `ru_RU-ruslan-medium`, `ru_RU-dmitri-medium`, `ru_RU-denis-medium` — русские голоса существуют только в качестве `medium`.

> 💡 Браузерный движок (`browser`) — тоже бесключевой вариант: распознавание через `SpeechRecognition`, озвучка через `speechSynthesis`. Он работает без сервера, но в Chrome требует сети и доступен не во всех браузерах.

После изменения **перезапустите `dsh web`** для применения. Приоритет: **Панель настроек > cordis.patch.yml (`asr.<движок>`/`tts.<движок>` > старые плоские ключи) > переменные окружения > значения по умолчанию**.

## 8. Принцип работы (для программистов)

Плагин разделен на **хост-часть** (Node) и **браузерную часть** (React bundle), взаимодействующие через HTTP-маршруты:

```
Браузерная часть (lib/client.js)              Хост-часть (lib/index.js)
┌──────────────────────────┐    ┌─────────────────────────────────────┐
│ 🎤 Кнопка / клавиша запуска    │    │ POST /dsh-voice-chat/stt  речь→текст    │
│ MediaRecorder запись        │───▶│  (siliconflow / groq / mimo ASR)    │
│ blobToWav автоматическая конвертация        │    │ POST /dsh-voice-chat/tts   текст→речь    │
│ Детектирование тишины (AnalyserNode)   │    │ POST /dsh-voice-chat/speak текст→речь    │
│ Одноканальное воспроизведение (механизм поколений)      │◀───│  ① LLM пересказ (следует за фактической моделью текущего диалога)    │
│ sessionStorage защита от повторного воспроизведения      │    │  ② edge-tts / MiMo TTS синтез аудио       │
│ 🔊 Отключение звука / 🔔 Звуковые сигналы        │    │ GET  /dsh-voice-chat/settings предоставление конфигурации  │
│ Браузерный ASR/TTS (Web Speech API)      │    │ GET/POST /dsh-voice-chat/local/* офлайн-движок       │
│ Постоянный диалог + перебивание голосом  │    │ (py/server.py: faster-whisper + Piper)  │
└──────────────────────────┘    └─────────────────────────────────────┘
```

**Двойной протокол ASR**: URL заканчивается на `/chat/completions` → MiMo-подобный chat-протокол (аудио base64 data URL в messages.content.input_audio, поддерживаются только wav/mp3); в противном случае используется стандартный OpenAI протокол `/audio/transcriptions` multipart (webm загружается как есть).

**Конвертация WAV на стороне браузера**: MiMo и другие ASR по chat-протоколу принимают только wav/mp3, но браузерная запись выдаёт webm/ogg/mp4. `blobToWav` использует Web Audio API (`decodeAudioData` → `OfflineAudioContext` передискретизация 16kHz моно → рукописный заголовок PCM16 WAV) для конвертации, без зависимости от ffmpeg.

- **Пересказ** использует встроенный LLM-сервис harness (`ctx.llm.stream`); клиент передаёт provider+model текущего диалога, поэтому пересказ всегда использует ту же LLM, что и текущий диалог;
- **Одноканальность** использует счётчик «поколений воспроизведения», при возврате асинхронного запроса с несоответствующим поколением ответ отбрасывается, что исключает наложение звуков;
- **Браузерные движки** не ходят на сервер: ASR — `SpeechRecognition` с языком `speechLang`, TTS — `speechSynthesis` со скоростью `ratePercent / 100`;
- **Офлайн-движок**: `lib/local-engine.js` управляет portable Python (astral-sh/python-build-standalone), venv с faster-whisper и piper-tts, предзагрузкой моделей и дочерним процессом `py/server.py`; сервер — OpenAI-совместимый шимм (`/v1/audio/transcriptions`, `/v1/audio/speech`, `/health`) на стандартной библиотеке Python, поэтому хост общается с ним тем же кодом, что и с облачным движком;
- **Скорость и язык речи** применяются ко всем движкам: Edge — SSML `rate`, пользовательский TTS — параметр `speed`, локальный и браузерный TTS — параметр скорости synthesis, а для движков без нативной скорости — `audio.playbackRate`.

## 9. Устранение неполадок (FAQ)

| Проблема | Причина | Решение |
|---|---|---|
| Озвучивание — **дословный текст** | ① Ответ ≤50 символов (так задумано) ② Переключатель пересказа по умолчанию выключен | Настройки → voice chat отметить «сначала пересказ для длинных ответов» |
| Полностью нет звука | ① Браузер не поддерживает/доступ запрещён ② Состояние отключения звука 🔇 ③ Текущий движок TTS не настроен (см. следующую строку) | Сначала проверить кнопку 🔇; затем запустить `npm run diagnose:tts`, чтобы увидеть ошибки каждого движка |
| Браузерный движок не работает («браузер не поддерживает SpeechRecognition») | `SpeechRecognition` есть не во всех сборках: в Electron и в Chromium без доступа к Google Speech сервисам API отсутствует физически (это не лечится настройкой плагина) | Открыть DSH в Chrome/Edge с интернетом либо переключиться на локальный движок `local` (офлайн, работает везде) |
| Локальный движок отвечает «не установлен» | Portable Python / venv / модели ещё не подготовлены | Настройки DSH → голосовой чат → движок «Локальный» → кнопка «Установить локальный движок» и дождаться готовности (первая загрузка — несколько минут; фаза видна в блоке статуса). То же — `POST /dsh-voice-chat/local/install` |
| Локальный движок поднимается не на том порту | Порт берётся из адреса слота `local` в панели (по умолчанию `http://127.0.0.1:8765/v1`) | Привести «Base URL» и фактический порт в соответствие либо задать порт явно: `POST /dsh-voice-chat/local/start?port=8765` |
| Локальный движок не находит Python | В системе нет `python3`, а portable Python не скачан | Установить `python3` или задать путь к интерпретатору в `DSH_VOICE_PYTHON` |
| Локальный движок: «venv есть, но faster-whisper / piper-tts не импортируются» | `pip install` отработал с ошибкой или пакеты установлены частично | Раскрыть «Последние строки журнала установки»; удалить `<dataDir>/venv` и нажать «Установить локальный движок» заново |
| Локальный движок: ошибка `open() got an unexpected keyword argument 'metadata_errors'` | Старый сервер отдавал путь к файлу во внутренний декодер faster-whisper, а в свежем PyAV параметра `metadata_errors` больше нет | Обновить плагин до v0.6.1 — сервер теперь декодирует аудио сам (`py/server.py`) и проблемный вызов не используется |
| Локальный движок: «Модели не загружены» | huggingface.co недоступен (прокси, антивирус, региональный доступ) | Причина есть в тексте ошибки и в журнале; задать зеркало `DSH_VOICE_PIPER_BASE` / `HF_ENDPOINT`, либо скачать модели вручную (см. 7.1) |
| Голос Piper не найден | Русские голоса Piper существуют только в качестве `medium` | Использовать `ru_RU-irina-medium`, `ru_RU-ruslan-medium`, `ru_RU-dmitri-medium` или `ru_RU-denis-medium` |
| Есть звуковые сигналы, но **не озвучивает** (или только роботизированный голос браузера) | Движок TTS/адрес/ключ не настроены: при ошибке интерфейса 400/502 фронтенд последовательно деградирует до `/tts`, в конце используется резервный TTS браузера | Открыть настройки → voice chat → настройки озвучивания, проверить Base URL / API Key для «текущего движка»; Base URL для MiMo можно оставить пустым (по умолчанию https://api.xiaomimimo.com/v1) |
| MiMo/облачный TTS сообщает «в ответе нет аудиоданных»/«пустой ответ» | Сетевой уровень хост-процесса обрабатывает **сжатый ответ** как пустой (тот же запрос напрямую без dsh работает) | С v0.4.1 плагин добавляет `Accept-Encoding: identity` для исходящих запросов и требует отсутствия сжатия; при сохранении проблемы диагностировать по `HTTP/статус/content-encoding/body` из сообщения об ошибке |
| Нажатие 🎤 не реагирует | Не предоставлены права на микрофон | Нажать «микрофон» слева от адресной строки и разрешить доступ |
| Повторное озвучивание при входе в сессию | Разные браузеры/очищен sessionStorage | Нормально: защита от повторного воспроизведения запоминается по сессиям браузера |
| Ошибка распознавания ASR (400/502) | ① Неправильный ключ ② Неправильный URL для MiMo ASR (требуется полный chat/completions endpoint) ③ Неподдерживаемый формат аудио | Пользователи MiMo проверить, что URL заканчивается на `/chat/completions`; проверить ключ |
| После переключения движка ключ/адрес «не похож на указанный» | Старая версия (≤0.3.x) хранила по одной конфигурации для ASR/TTS, переключение движков перезаписывало друг друга | v0.4+ имеет раздельное хранение по движкам; старая конфигурация автоматически мигрирует при первом запуске, проверить `asr.<движок>` / `tts.<движок>` в `settings.local.json` |
| Edge TTS сообщает о недействительном голосе / нет звука при озвучивании (голос — имя MiMo или пользовательского голоса) | В старой версии Edge/MiMo использовали одно поле голоса | v0.4+ голоса разделены по движкам; для Edge оставить пустым, будет использоваться встроенный Сяосяо |
| Ошибка распознавания «ошибка конвертации формата записи» | Ошибка конвертации blobToWav (очень редко) | Обновить страницу и повторить; проверить консоль F12 |

**Ключ к диагностике**: при любой проблеме сначала проверить два места — консоль браузера F12 (с префиксом `[dsh-voice-chat]`) и логи хоста (`%TEMP%\dsh-web-restart*.log`).

**Однокомандная диагностика цепочки озвучивания** (рекомендуется запустить в первую очередь):

```bash
cd <каталог-плагина>            # клон этого репозитория
npm run diagnose:tts            # или: node test/diagnose-tts.mjs
```

Он считывает активную конфигурацию из `settings.local.json`, выполняет **реальный запрос синтеза для каждого движка** и напрямую вызывает обработчики `/tts`, `/speak` плагина, выводя результат вида:

```
=== Активная конфигурация ===   Движок TTS: mimo …
=== 1. Edge TTS (Microsoft, бесплатно)===    ✓ Синтез успешен 14544 байт → %TEMP%\dsh-tts-edge.mp3
=== 2. MiMo TTS ===               ✓ / ✗ HTTP 4xx: …
=== 5. Тестирование маршрутов хоста ===            GET /tts → 200, аудио 16056 байт
```

Где ✗ — там точка разрыва: отсутствие конфигурации смотреть в 1-м разделе, ключ/API во 2-м и 3-м разделах, сетевой доступ хост-процесса в 5-м разделе (если здесь ✗, а во 2-м разделе прямое подключение ✓, значит проблема в **исходящем соединении/прокси хост-процесса**, а не в конфигурации плагина).

## 10. Рекомендации по безопасности

- **Ключи ASR/TTS** хранятся в `settings.local.json` (сохранено через панель настроек) или `cordis.patch.yml`, не отправляйте эти файлы в публичные репозитории; более надёжный способ — использовать переменные окружения (`DSH_VOICE_ASR_KEY` и т.д.);
- Пересказ использует собственный LLM harness, оплата идёт по тому же счёту, что и диалог с агентом (около сотен токенов на каждый пересказ);
- Плагин имеет те же права, что и агент, перед установкой убедитесь в надёжности источника;
- **Браузерный движок** отправляет аудио сервису распознавания самого браузера (в Chrome — серверам Google), то есть запись покидает машину: для полностью локальной обработки используйте движок `local`;
- **Офлайн-движок** скачивает portable Python, pip-пакеты и модели из внешних источников при первой установке; все файлы складываются в `~/.local/share/dsh-voice-chat/` и удаляются вместе с этим каталогом;
- Локальный сервер слушает только `127.0.0.1` и не требует ключей, но он выполняет код с правами вашего пользователя — не запускайте его на общих машинах.
