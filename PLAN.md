# План: dsh-voice-chat → русский + скорость речи + локальные движки

## Проверенные факты
- **Edge TTS русские голоса**: ровно два — `ru-RU-SvetlanaNeural`, `ru-RU-DmitryNeural`
- **Piper (TTS)**: `piper-tts 1.8.0` на PyPI, wheel `abi3` под linux-x64/aarch64/mac/win, Python ≥3.9, в колесе лежат `piper/download_voices.py` и `espeak-ng-data`. Русские голоса **только `medium`**: `ru_RU-irina`, `ru_RU-ruslan`, `ru_RU-dmitri`, `ru_RU-denis`.
- **faster-whisper**: `1.2.1`, Python ≥3.9.
- **Portable Python**: `astral-sh/python-build-standalone`, тег `20261003`, `cpython-3.12.15-*-install_only_stripped.tar.gz` = 34 МБ linux / 22 МБ win / 25 МБ mac.

## Этап 1 — Локализация UI на русский
1. `lib/client.js` (~90 строк): форма настроек, опции движков, примечания, статусы, хинты, тултипы, label сайдбара.
2. `lib/index.js`: все ошибки, всплывающие в баблах → русский.
3. `SPEAK_SYSTEM_PROMPT` → русский промпт + инструкция языка.
4. Инструкция MiMo TTS и все сообщения `lib/edge-tts.js` → русский.
5. **Не трогаем**: идентификаторы голосов `冰糖/茉莉/...`, консольные логи, комментарии в коде.

## Этап 2 — Язык речи + русские голоса
1. Новая настройка **`speechLang`** (select: `ru-RU | zh-CN | en-US | ja-JP`, дефолт `ru-RU`).
2. `VOICE_PRESETS` → `ru-RU-SvetlanaNeural`, `ru-RU-DmitryNeural` первыми.
3. Дефолтный голос → `ru-RU-SvetlanaNeural` в 4 местах.
4. Fallback `xml:lang` в `edge-tts.js`: `zh-CN` → `ru-RU`.

## Этап 3 — Ползунок скорости речи (ко всем движкам)
1. Настройка **`ratePercent`** (50–200, шаг 5, дефолт 110).
2. UI: `<input type="range">` в секции «Настройки озвучки».
3. Применение:
   - **Edge** → SSML rate
   - **custom/OpenAI** → параметр `speed`
   - **браузерный fallback** → `u.rate`
   - **MiMo и остальные** → `audio.playbackRate` (только если движок без нативной скорости)

## Этап 4 — Браузерный движок STT + TTS
1. **ASR `browser`**: `SpeechRecognition|webkitSpeechRecognition` вместо MediaRecorder.
2. **TTS `browser`**: прямой вызов `speechSynthesis`, режим `synthesize:false` в `/speak`.
3. Слот голоса `browser.voice` + datalist из `getVoices()`.

## Этап 5 — Локальный Python-движок (faster-whisper + Piper)
1. Новые движки **`local`** в обоих списках.
2. **`py/server.py`** (stdlib only): OpenAI-совместимый шим.
3. **`lib/local-engine.js`**: менеджер (Python, venv, модели, spawn/kill), single-flight `install()` с фазой в `status()`, `ensureStarted()` для автозапуска.
4. Routes: `GET /local/status`, `POST /local/install`, `POST /local/start?port=`, `POST /local/stop`.
5. UI: блок статуса (Python / зависимости / модели / сервер) + кнопки установки/запуска/остановки; голос Piper — в общем списке.
6. Движок `local` работает **без ключа**: `transcribe`/`synthesizeWithCustomTts` не требуют `apiKey` для `local` и не шлют `Authorization`; сервер поднимается перед первым `/stt` и `/tts`; Piper отдаёт WAV ⇒ `Content-Type: audio/wav`.

## Этап 11 — Совместимость faster-whisper со свежим PyAV, удаление движка, тёмные списки
1. **Регрессия распознавания**: faster-whisper 1.2.1 внутри зовёт
   `av.open(..., metadata_errors="ignore")`, а в PyAV >=14 такого параметра нет →
   `TypeError: open() got an unexpected keyword argument 'metadata_errors'` на любой
   свежей установке. `py/server.py` теперь декодирует аудио сам (`_decode_audio`,
   float32 16 кГц моно) и отдаёт модели numpy-массив; tempfile-путь убран.
2. **Язык распознавания** из общей настройки «Язык речи» передаётся в multipart
   (`language`) — раньше Whisper угадывал и на русской речи давал en.
3. **Удаление**: `localEngine.remove()` + `POST /local/remove?keepModels=` (останавливает
   сервер, сносит python/venv/models/logs, сбрасывает кэш проверки зависимостей),
   `status().hasFiles/installedFiles`, кнопка в UI с двойным подтверждением.
4. **Оформление списков**: `color-scheme` (light/dark по фону DSH) — нативный выпадающий
   список больше не белый на тёмном, выбранный вариант видно сразу.

## Этап 12 — Ozвучка и выбор движка (регрессии)
1. В `playOne` было `currentModel && current.model` — переменной `current` не существует,
   поэтому **любой** запрос `/speak` падал с `ReferenceError` ещё до `fetch`: озвучка не
   работала ни для одного движка, включая локальный Piper. Исправлено на
   `currentModel.model`; тест с непустым `modelDirectories` ловит возврат бага.
2. Гонка настроек: движок читался из `settingsValue`, который на первом нажатии микрофона
   мог быть ещё `null`. Добавлен `readySettings()` — старт записи и `playOne` ждут первую
   загрузку; при недоступных настройках показывается подсказка вместо записи «не туда».
3. Сервер больше не врёт про движок `browser`: `/stt` и `/tts`/`/speak` отвечают 400 с
   объяснением (Web Speech API / speechSynthesis), а не «не настроен ключ» и не молча
   подменяют озвучку через Edge TTS.

## Этап 16 — Полная работоспособность (v0.8.0)

Пользовательский отчёт: при переключении режимов в настройках — серый экран;
скачивается модель `small` независимо от выбора; локальное распознавание не работает;
в консоли `text.replace is not a function`, React #310 и голые `500 fetch failed`.

### Найденные и исправленные причины

1. **Серый экран настроек (React #310).** `browserAsrCheckBlock()` вызывалась как
   обычная функция прямо из тела `VoiceChatSettingsSection`. Три её `useState`
   принадлежали родителю и появлялись/исчезали вместе с `engine === "browser"` —
   классический «hooks order changed». Теперь это компонент `BrowserAsrCheckBlock`.
   Закреплено тестом на неизменность числа хуков формы при смене движка.
2. **Тесты писали в боевой `settings.local.json`.** Путь вычислялся от
   `import.meta.url` и не переопределялся: прогон тестов оставлял в конфиге
   `http://127.0.0.1:46805` и `http://127.0.0.1:59998`, то есть «Локальный» движок
   с мёртвым портом → `500 fetch failed`. Теперь путь переопределяется через
   `DSH_VOICE_SETTINGS_FILE`, тесты работают во временном каталоге.
3. **Всегда скачивался `small`.** `lib/local-engine.js` читал `config.whisperModel`
   из cordis-конфига (где такого ключа нет) и замыкал его в `const` на момент
   создания менеджера. Выбор модели из панели до установщика не доходил вовсе.
   Добавлен `setTargets({whisperModel, piperVoice})`, хост синхронизирует цели из
   живых настроек перед каждой операцией, `ensureModels` передаёт `--piper-voice`.
4. **«Модели готовы» ≠ нужная модель.** `modelsState()` принимал любой снапшот
   whisper. Теперь сверка строгая и единая с `downloadedModels()` (общий
   `whisperSnapshotMatches`), а в UI видно, какая модель выбрана.
5. **Докачать сменившуюся модель**: `downloadModel()` + `POST /local/download-model`.
   Скачивание и удаление выбранной модели — кнопками прямо у списка модели в
   настройках, в блоке статуса осталась «Докачать модель <имя>» и список
   «Не скачаны» с кнопкой на каждую. `POST /local/install` и `GET /local/status`
   принимают `?model=`/`?voice=`: несохранённый выбор в форме доходит до
   установщика (раньше цели всегда перезаписывались настройками из файла).
6. **`py/server.py` кэшировал одну модель навсегда.** Первый запрос (обычно `small`)
   определял модель для всех последующих — выбранная `medium` молча игнорировалась.
   Кэш теперь по имени; веса не качаются на лету (был риск многогигабайтной загрузки
   прямо на `/stt`), вместо этого `409` с перечнем скачанного.
7. **`cgi.FieldStorage` удалён в Python 3.13** — на системном `python3` 3.13+ всё
   распознавание падало с `ImportError`. Написан свой минимальный multipart-парсер.
   Добавлены `GET /health` со списком реально скачанных моделей и `GET /v1/models`.
8. **Один процесс на все порты.** `ensureStarted`/`start` проверяли «есть ли child»,
   не сверяя порт: при разных портах ASR/TTS второй запрос уходил на чужой порт.
   Теперь сервер перезапускается при смене порта, и только после `probe` нового
   порта (чтобы не ронять работающий сервер зря).
9. **Голое `fetch failed` → 502 с адресом и подсказкой** для всех четырёх движков
   (`fetchDiagnostic`, в том числе chat-протоколов MiMo), плюс таймаут запроса,
   лимит тела и разбор 401/403/404/409 от провайдера.
10. **`playOne` держал первый снимок настроек** — смена движка/языка/скорости не
    влияла на озвучку. Зависимости хуков дополнены.
11. **`GET /tts?text=`** упирался в лимит длины URL на длинных ответах — добавлен
    `POST /tts` с телом, лимит синтеза вынесен в `MAX_SPEECH_CHARS` (было 2000 в
    четырёх местах), длинный текст больше не режется на середине.
12. **Язык распознавания не доезжал** до faster-whisper при незаданном значении —
    Whisper угадывал и на русской стабильно выбирал `en`. Теперь дефолт `ru-RU`
    один и тот же в UI и в запросе.
13. **Гонка записи настроек**: параллельные `POST /settings` затирали друг друга —
    записи выстраиваются в очередь; битый JSON больше не выглядит как успешное
    сохранение.
14. **Сторож чужого бага хоста**: `dsh-client-ui-conversation` делает
    `inputActions.setDraft(storedDraft)`, а переигровка `localStorage` идёт целиком
    без слияния с начальным состоянием — битый `dsh.conversation.*` давал
    `setDraft(undefined)` и `text.replace is not a function` на всём вводе сессии.
    `repairPersistedDrafts()` приводит `draft` к строке до рендера.
15. **`sendText` приводит текст к строке** на входе: любое не-строковое значение
    роняло ввод сессии.

### Архитектура

- `lib/shared.js` — константы и чистые функции без зависимостей от Node и браузера.
  `lib/index.js` импортирует их; `lib/client.js` остаётся самодостаточным (require
  хоста не резолвит относительные пути), паритет копий закреплён

- Рекомендуемое дальнейшее разбиение `lib/client.js` (2400 строк) на

## Этап 17 — Разбиение на модули (v0.8.0)

### Серверная половина — настоящие ESM-модули

`lib/index.js` (1591 строка) распался на части по ответственности:

| Модуль | Что внутри |
|---|---|
| `lib/shared.js` | константы движков и чистые функции без Node/браузерных зависимостей |
| `lib/settings.js` | путь к файлу, чтение/запись, нормализация, слияние, миграция, разбор cordis-конфига |
| `lib/net.js` | исходящие запросы, `fetchDiagnostic`, таймауты, лимит тела, чтение тел, JSON-ответы |
| `lib/engines/asr.js` | распознавание: multipart и chat-протокол |
| `lib/engines/tts.js` | синтез у внешних движков: OpenAI-совместимый и MiMo |
| `lib/rewrite.js` | разговорный пересказ через LLM harness |
| `lib/index.js` | только `apply()`, HTTP-маршруты и связывание (776 строк) |

`lib/index.js` сохранил плоский экспорт для тестов и `diagnose-tts` — тестам не
нужно знать, где что лежит. Побочная польза: `CHAT_ASR_URL_RE` переехал в
`shared.js`, потому что на него опирались и разбор протокола, и миграция
настроек, — то есть граница модулей сразу указала на спрятанную связь.

### Браузерная половина — исходник разбит, артефакт один

Разбить `lib/client.js` (2400 строк) на runtime-модули нельзя: `require()`
хоста резолвит только пакеты из графа, относительные импорты не работают.
Поэтому исходник разложен по `src/client/*.js` (10 кусков), а
`scripts/build-client.mjs` склеивает их в `lib/client.js`. Артефакт не изменился
ни байтом — правки в рантайме нет, выигрыш только в читаемости.

Главный риск такой схемы — разъезд (правка в `src/`, забытая пересборка, «код
правильный, баг есть`). От него защищают `npm run check:client` и тест
`test/client-build.test.mjs`.

Куски не модули: они делят лексическую область `factory`, порядок склейки
значим, изоляции нет. Это осознанно — так видно, что шина настроек и оба
компонента связаны общими ссылками. Настоящее разделение потребовало бы
объявления ещё одного пакета в `dsh.client.inject`.

### Комментарии

Китайские комментарии переведены на русский во всём коде и тестах. Оставлены
только идентификаторы голосов MiMo (`冰糖`, `茉莉`, …) — это названия
производителя, участвующие в миграции старых настроек.

## Этап 18 — Локальный Piper перестал озвучивать (v0.8.2)

Пользовательский отчёт: «локальный piper не воспроизводит аудио», в консоли DSH —
`сервер остановлен (сигнал SIGTERM)` и `ECONNRESET` на `/v1/audio/speech`.

Найдено три причины, все в локальном движке:

1. **Мёртвая блокировка Piper (главная, живёт с v0.5.0).** `_synthesize()` брал
   `_piper_lock` и внутри вызывал `_load_piper()`, который брал его же.
   `threading.Lock` не реентерабелен → первая озвучка Piper намертво зависала:
   ни звука, ни ошибки, запрос не возвращался никогда. Исправлено на `RLock`,
   попутно убран мёртвый `import numpy`.
2. **Несовместимость с новым piper-tts.** Требование `piper-tts>=1.2.0` ставит
   1.8.x, где `synthesize_stream_raw()` удалён (ветка piper1-gpl, синтез переписан
   на `synthesize()` + `SynthesisConfig(length_scale=…)` и `AudioChunk`).
   Старый код падал бы `AttributeError` → 500. Теперь `_iter_pcm()` определяет
   ветку API по факту и умеет обе: байты из `synthesize_stream_raw`,
   байты из `synthesize()` (1.2), объекты `AudioChunk` (1.3+) и вариант только с
   `audio_int16_array`. Верхняя граница зависимости зафиксирована (`<2`).
3. **Гонка запуска сервера.** `/stt` и `/speak` приходят внахлёст (в постоянном
   диалоге — постоянно), оба видели `child === null` и оба шли дальше: второй
   убивал сервер, только что поднятый первым, а `catch` упавшего `start()` гасил
   уже чужой процесс. Отсюда `SIGTERM` и `ECONNRESET` на идущем запросе — регрессия
   после моего же перевода `start()` на порт-зависимый. Исправлено: `startOnce()`
   (single-flight, как `installPromise`) и `stopProcess(proc)` — гасит конкретный
   процесс, а не «текущий child». Переключение порта стало атомарным: старый сервер
   отвязывается и гасится только после успешного старта нового.

Тесты: +14 (`test/py-piper-compat.test.py` — фейковый piper в трёх API-видах,
плюс проверка вложенных блокировок на настоящем пути; два теста гонки запуска в
`test/local-model-selection.test.mjs`). Тест на блокировку проверен на старом коде:
падает с «_synthesize() не вернулся за 6 с — deadlock на _piper_lock».

## Этап 19 — Скорость горячего пути (v0.8.3)

Пока «микрофон жёлтый» объяснялось зависанием, оставалась вторая половина проблемы:
даже когда запросы не висели, локальный движок отвечал медленно.

1. **`ensureStarted()` звал полный `status()`.** Тот поднимал до четырёх процессов
   Python (`--version`), пробовал импорт `faster_whisper`/`piper` (таймаут 90 с) и
   рекурсивно обходил каталог моделей. На каждый `/stt` и `/speak`. Добавлена
   дешёвая `venvReady()` — для решения «можно ли стартовать» хватает проверки
   интерпретатора, результат кэшируется на 2 с.
2. **`status()` считался на каждый запрос и на каждый опрос панели** (раз в 2 с).
   Теперь два уровня: параллельные вызовы ждут один расчёт, а повторный запрос в
   пределах секунды берёт готовый ответ. `start()` переиспользует проверку
   интерпретатора вместо нового запуска Python.
3. **Первый запрос платил за чтение весов с диска.** Добавлен `GET /warm` в
   `py/server.py` (загружает модель и голос, отдаёт время и понятные причины
   неудачи) и фоновый `warmUp()` после старта сервера, не чаще раза в минуту.

Кэши сбрасываются при изменении окружения (install/remove/downloadModel/
removeModel) и при смене целей `setTargets()` — иначе `status()` продолжал бы
показывать прежнюю выбранную модель.

Тест `test/local-engine-fast-path.test.mjs` считает не скорость (она зависит от
машины), а число запусков Python: при поднятом сервере шесть запросов дают ровно
0, на холодном пути — 2 вместо 5, повторный `status()` — 0. На коде до правки
три из четырёх проверок падают.

## Этап 20 — Модель распознавания: выбор, скачивание и удаление (v0.8.4)

Два вопроса от пользователя: «почему выбрал `tiny`, а скачался `small`» и «как
модель докачать, если удалить можно».

1. **Установщик смотрел только в `settings.local.json`.** Выбор в списке формы
   не сохранён — а кнопка «Установить» уже качает. Теперь `POST /local/install`
   и `GET /local/status` принимают `?model=`/`?voice=`, клиент шлёт выбранное в
   форме явно, имя модели проверяется до старта загрузки (`400` на мусор).
2. **Опрос статуса затирал цель.** Хост синхронизирует цели из настроек на
   каждом запросе, поэтому через 2 с после старта установки `tiny` статус снова
   показывал `small`. В `setTargets(next, picked)` цели из файла и явный выбор
   из UI разведены: явный держится до реального изменения файла.
3. **Кнопка «Докачать модель» молчала о модели и гасла после установки.** Подпись
   теперь называет модель, кнопка не выключается по `modelsReady` (после удаления
   модели она снова нужна), а рядом появился список «Не скачаны: …» с кнопкой на
   каждую модель — скачать можно любую, а не только выбранную.
4. **Управление моделью переехало к её списку.** Под «Модель распознавания» в
   настройках показывается, есть ли модель на диске и сколько весит, и две
   кнопки: «Скачать <модель>» / «Удалить» (удаление — по идентификатору
   каталога снапшота с диска, а не по имени модели).

Тесты: `test/host-routes.test.mjs` (цели установки из `?model=`/`?voice=`),
`test/client-settings.test.mjs` (кнопки у списка модели меняют состояние),
`test/client-regressions.test.mjs` (подпись кнопки и её живучесть).
