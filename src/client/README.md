# Исходники браузерной половины

`lib/client.js` — **генерируемый артефакт**. Правьте куски здесь, потом
`npm run build:client`.

## Почему так

Хост грузит браузерный модуль как

```js
window.__ModuleLoader__.load({ id: "dsh-voice-chat", factory: (require) => { … } })
```

и `require()` в нём умеет только **пакеты из графа модулей**. Относительные
импорты вида `"./shared.js"` не резолвятся (проверено по
`@deepseek-ai/dsh-client-modules`: спецификатор либо точное имя пакета
`@scope/name`, либо имя без `/`). Значит в рантайме файл обязан остаться
**одним** — иначе плагин просто не загрузится.

Чтобы это не превращало `client.js` в простыню на 2400 строк, исходник разбит
на куски по ответственности, а `scripts/build-client.mjs` их склеивает.

## Чего куски НЕ делают

Куски **не модули**. Они попадают в общую лексическую область `factory` и видят
объявления друг друга напрямую:

- порядок в `CLIENT_PARTS` значим — `const` виден только ниже себя;
- между кусками нет изоляции: общий `React`, общие `SECTION_STYLES`, общая шина
  настроек;
- ни один кусок нельзя переместить или выбросить независимо.

Побочный эффект задуман: видно, что шина настроек, `VoiceChatButton` и страница
настроек связаны общими ссылками, а не через экспорт. Когда понадобится
настоящее разделение — правильный путь это объявить в `package.json`
`dsh.client.inject` ещё один пакет, а не импорт.

## Куски

| Файл | Что внутри |
|---|---|
| `header.js` | `window.__ModuleLoader__.load`, `require("react")`, деструктуризация хуков |
| `01-core.js` | мелкие помощники, константы движков ASR/TTS, списки моделей и голосов, порт/адрес `local`, слоты настроек, разбор ответов `/settings` |
| `02-icons.js` | плоские SVG-иконки (стиль Feather) и компонент `Icon` |
| `03-styles-voices.js` | `SECTION_STYLES` (объект стилей всех полей) и пресеты голосов Edge/MiMo |
| `04-hotkey-browser-asr.js` | разбор и подпись сочетаний клавиш, диагностика Web Speech API |
| `05-local-engine-box.js` | блок управления локальным движком: статус, установка, модели, порт, тема списков |
| `06-settings-bus-and-section.js` | шина настроек, `useSettings`/`readySettings`, подписка на модель диалога, страница настроек и `BrowserAsrCheckBlock` |
| `07-voice-chat-button.js` | кнопки 🎤/🔊 у поля ввода: запись, распознавание, очередь озвучки, постоянный диалог, горячая клавиша |
| `08-plugin.js` | `repairPersistedDrafts` и `apply()` — регистрация в слотах `settings.section` и `conversation.input.right` |
| `footer.js` | хвост модуля (`exports.apply`, `exports.inject`) |

## Правила

1. Между кусками ровно одна пустая строка — её ставит сборщик, вручную не добавлять.
2. Куски не начинаются с середины объявления: первый содержательный символ —
   начало комментария (`test/client-build.test.mjs` это проверяет).
3. После правки: `npm run build:client && npm test`.
4. `npm run check:client` — только проверка свежести артефакта (в CI/перед
   коммитом), ничего не перезаписывает.
5. Тест `test/client-build.test.mjs` падает, если `lib/client.js` разошёлся с
   кусками. Это главная защита схемы: забытая пересборка выглядит как «правка
   не работает».

## Общие константы

`lib/shared.js` — единственный источник правды для констант, но **клиент его не
импортирует** (см. выше) и держит копии. Паритет копий и клиента, и сервера
закреплён `test/shared-parity.test.mjs`: правку вносим здесь и в `lib/shared.js`
одновременно.
